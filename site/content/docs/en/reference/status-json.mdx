---
title: status --json
description: The machine-readable troop snapshot, and the task schema behind it.
---

```bash
vx status --json
```

prints one JSON object. It is read-only and adds nothing to the persisted task: `tasks` is exactly the `Task` schema vexillum itself reads from `<project root>/tasks/*.json`, so a consumer such as the [muster skill](/docs/guides/muster-skill) never works from a separate reinterpretation. Grouping, filtering and judgment calls (what counts as "needs attention", GitHub enrichment) belong to the consumer.

```json
{
  "schema_version": 3,
  "generated_at": "2026-09-24T12:00:00Z",
  "project_root": "/abs/path/to/this project's ~/.vexillum namespace",
  "tasks": []
}
```

With no tasks, `tasks` is `[]`, never `null`. Tasks are ordered most recently updated first.

## Task fields

| Field | Type | Notes |
| --- | --- | --- |
| `schema_version` | number | version of the task file schema |
| `id` | string | 16 hex characters |
| `kind` | `"mission"` or `"scout"` | |
| `prompt` | string | the original prompt |
| `status` | string | `pending`, `running`, `blocked`, `done`, `failed`, `interrupted`, `shipped`, `unconfirmed`; see [Missions and scouts](/docs/concepts/missions-and-scouts). A `shipped` task is waiting for its pull request to be merged, not stuck |
| `created_at`, `updated_at` | RFC 3339 time | |
| `camp_slot`, `camp_path`, `camp_branch` | number, string, string | set once a camp is acquired |
| `camp_base` | string | branch the camp was forked from; may be empty |
| `exit_code`, `output` | number, string | `output` is the captured transcript |
| `herdr_workspace_id`, `herdr_tab_id`, `herdr_pane_id`, `herdr_agent_name` | string | the soldier's herdr pane |
| `agent_not_found_since`, `idle_unconfirmed_since` | time | when the sentinel first saw the condition |
| `redispatches` | number | how many times the task was re-dispatched |
| `model`, `effort` | string | the soldier's choice; empty means claude's default |
| `decision` | object | present once the task has blocked at least once |
| `amendments` | array | instructions the general gave after dispatch, via `vx prompt` and `vx decide` (not `--dismiss`); see below |

Optional fields are omitted when empty.

## decision

| Field | Notes |
| --- | --- |
| `question` | what the soldier asked |
| `options` | choices it offered, if any |
| `asked_at` | when it blocked |
| `answer`, `answered_at` | set after [`vx decide`](/docs/reference/cli/decide) |
| `kind` | how it must be answered: a selector overlay is answered with a key press, anything else as text |
| `dismissed` | `true` when cleared with `vx decide --dismiss` instead of answered; `answered_at` is set, `answer` is not |

A task in `blocked` always carries its question here, not just the word "blocked".

## amendments

| Field | Notes |
| --- | --- |
| `text` | what the general said; for `vx decide`, the question and the answer (a selector pick as the option's text). At most 2000 characters, longer text is cut and marked `[truncated]` |
| `at` | RFC 3339 time it was recorded |
| `source` | `vx prompt` or `vx decide` |

Omitted when empty. A task keeps its 20 most recent amendments. `prompt` never changes: [`vx ship`](/docs/guides/land-vs-ship) gives the tribunal review the prompt followed by the amendments, so what the general asked for later counts as requested. Only `vx prompt` and `vx decide` write them, into the task's state file, never into a file in the camp.

## Compatibility

Treat unknown fields as additive.
