vexillum is a CLI orchestrator for code agents, written in Go. You talk to one agent, the **commander** (Claude Code). It dispatches **soldiers** (more Claude Code sessions) in parallel. Each soldier works in its own git worktree (a **camp**) so parallel work never collides, and hands back either a change to land (a **mission**) or a written report (a **scout**). A background **sentinel** watches the soldiers and wakes the commander only when something needs attention.

You do not learn a new interface: you keep talking to Claude Code, and the commander calls `vx` for you.

```text
> dispatch a soldier to refactor the payment module
Bash(vx dispatch "refactor the payment module" --kind mission --model sonnet)
```

## What vexillum is, and is not

- **A single Go binary.** It does deterministic plumbing: it creates worktrees, starts sessions, tracks state on disk, and refuses unsafe operations. It installs by Homebrew or a curl script, with no runtime dependencies.
- **Not the brain.** The commander's judgment (when to dispatch, which model to pick, when to ask you) lives in markdown: a short core in a block of your own `AGENTS.md` (or `CLAUDE.md`), plus [skills](/docs/concepts/skills) the commander loads when it needs them. `vx init` writes them into your project, after asking. You can read and edit them. See [AGENTS.md and rules](/docs/concepts/agents-md-and-rules).
- **Claude Code only, for now.** The soldier harness is Claude Code. Other harnesses are not supported yet. Contributions are welcome: see [Contributing](/docs/guides/contributing).
- **herdr for panes.** Soldiers run in [herdr](https://herdr.dev) panes. `vx doctor` checks for it but never installs it.

<Callout type="warn" title="Soldiers have full host access">
  A soldier runs Claude Code with `--dangerously-skip-permissions`, under your OS user, with no container or sandbox. The camp only bounds where its commits land. Nothing reaches your project's real history until you approve landing it. Never dispatch against a repository or machine where reading credentials would be a problem.
</Callout>
