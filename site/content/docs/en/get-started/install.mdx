title: Install
description: Install the vexillum binary with Homebrew or the curl script, pick a release channel, and check your environment.

vexillum supports macOS and Linux, on amd64 and arm64.

## Install the binary

<CodeBlockTabs defaultValue="brew">
  <CodeBlockTabsList>
    <CodeBlockTabsTrigger value="brew">brew</CodeBlockTabsTrigger>
    <CodeBlockTabsTrigger value="curl">curl</CodeBlockTabsTrigger>
  </CodeBlockTabsList>
  <CodeBlockTab value="brew">
```bash
brew install isaias-alt/tap/vexillum
```
  </CodeBlockTab>
  <CodeBlockTab value="curl">
```bash
curl -fsSL https://raw.githubusercontent.com/isaias-alt/vexillum/canary/scripts/install.sh | bash
```
  </CodeBlockTab>
</CodeBlockTabs>

The script:

1. Detects your OS and architecture;
2. Uses Homebrew if `brew` is on your PATH (`brew install isaias-alt/tap/vexillum`, or `brew upgrade` when the formula is already installed);
3. Otherwise downloads the release archive for your platform and **verifies its sha256 checksum** against the release's `checksums.txt`, refusing to install on a mismatch;
4. Installs the binary into `/usr/local/bin`, or into `~/.local/bin` when you cannot write to `/usr/local/bin` (it warns if that directory is not on your PATH);
5. Checks that a working `vx` now exists (in the install directory, the Homebrew prefix or your PATH) and exits with an error if it does not.

Without options it installs the latest **stable** release and never a pre-release. To try a canary build or install an exact version, pass `--channel canary` or `--version <tag>`; both are direct downloads that skip Homebrew. See [Release channels](/docs/get-started/release-channels).

Check it worked:

```bash
vx --version
```

## Install what vexillum orchestrates

vexillum does not install its tools; it checks for them.

| Tool | Needed for | Required |
| --- | --- | --- |
| [Claude Code](https://claude.com/claude-code) | the commander and every soldier | yes |
| [herdr](https://herdr.dev) | the panes soldiers run in | yes |
| `gh` (GitHub CLI) | `vx ship`, and landing a shipped PR | only for those |

Run the check any time:

```bash
vx doctor
```

`doctor` is read-only. It prints `[ok]` or `[missing]` for each tool, the herdr version, `~/.vexillum/`, whether the current project is initialized and is a git repository, and, for an initialized project, the state of the [vexillum block](/docs/concepts/agents-md-slot) in `AGENTS.md` or `CLAUDE.md`, whether `CLAUDE.md` imports `AGENTS.md` (when the block is in `AGENTS.md`), each [skill](/docs/concepts/skills), whether [`models.json`](/docs/reference/models-json) is valid, and the sentinel `Stop` hook: whether it is registered, whether it [finds vx from a bare environment](/docs/concepts/sentinel#the-hook-does-not-depend-on-your-path) and whether a sentinel is running:

```text
[ok] AGENTS.md vexillum block - current (en)
[ok] CLAUDE.md imports AGENTS.md
[ok] skill vexillum - installed, current
[ok] models.json - valid, 5 profiles
[ok] sentinel Stop hook - registered in .claude/settings.json
[ok] sentinel Stop hook finds vx - found with a minimal environment
[ok] sentinel - running, 1 Stop hook await(s) waiting
```

It exits non-zero when a required check fails. A `Stop` hook that cannot find vx is a `[warn]` with the fix, never a failure.
