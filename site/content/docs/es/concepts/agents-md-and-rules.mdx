## Dos archivos distintos

- **El `AGENTS.md` propio de vexillum** (en el repositorio de vexillum) gobierna cómo se construye vexillum. No es lo que recibís.
- **`.claude/rules/vexillum.md`** es el archivo de reglas del *producto*. `vexillum init` lo crea en tu proyecto. Claude Code lo carga en cada sesión, de forma incondicional - junto con el `AGENTS.md` o `CLAUDE.md` que el proyecto ya tenga, que vexillum nunca toca.

Esta es la decisión central del producto: la inteligencia del commander es markdown, el binario es plomería.

## Qué cubren las reglas

| Sección | Tema |
| --- | --- |
| Role check | Las reglas aplican solo al commander. Un soldier que las lea por accidente debe seguir su prompt de dispatch, y nunca despachar más soldiers. |
| Vocabulary, Authority | Los términos; una instrucción explícita tuya anula una regla, pero el commander debe decir cuál dejó de lado. |
| Tone | Cómo dirigirse a vos y cuándo dejar el color (las malas noticias se reportan sin adornos). |
| The sentinel | Qué significa el hook `Stop` y cómo reaccionar ante `interrupted`. |
| Dispatching a soldier | Siempre `vexillum dispatch`, nunca la herramienta de subagentes propia del commander. |
| Choosing a model and effort | La tabla de decisión de abajo. |
| Landing, Shipping, Releasing | Preguntar antes de aterrizar; hacer release enseguida. |

### Elegir modelo y effort

Gana la primera regla que coincide. vexillum valida los valores pero nunca los elige.

| # | Situación | Modelo y effort |
| --- | --- | --- |
| 1 | Scout cuya pregunta son hechos verificables de una fuente autoritativa | `haiku`, `low` |
| 2 | Scout que requiere criterio | `sonnet`, `medium` |
| 3 | Mission que es una edición mecánica trivial | `haiku`, `low` |
| 4 | Mission grande o ambigua de varios archivos, refactor riesgoso | `sonnet`, `high` |
| 5 | Pedís Opus explícitamente | `opus`, `high` |
| 6 | Nada de lo anterior aplica | `sonnet`, `medium` |

## Editar y actualizar

El archivo es tuyo para editar: ajustá la tabla, el tono, la postura de landing. `init` lo escribe una vez y nunca lo pisa; [`upgrade`](/es/docs/get-started/upgrading) lo refresca solo cuando no fue modificado, o con `--force`.

`vexillum init --global` escribe las reglas en `~/.claude/rules/vexillum.md`, y aplica la persona del commander a cada sesión de Claude Code de la máquina. Por eso es opt-in.
