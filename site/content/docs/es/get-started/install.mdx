vexillum soporta macOS y Linux, en amd64 y arm64.

## Instalá el binario

<CodeBlockTabs defaultValue="brew">
  <CodeBlockTabsList>
    <CodeBlockTabsTrigger value="brew">brew</CodeBlockTabsTrigger>
    <CodeBlockTabsTrigger value="curl">curl</CodeBlockTabsTrigger>
  </CodeBlockTabsList>
  <CodeBlockTab value="brew">
```bash
brew install isaias-alt/tap/vexillum
```
  </CodeBlockTab>
  <CodeBlockTab value="curl">
```bash
curl -fsSL https://vx.lucasco.dev/install | bash
```
  </CodeBlockTab>
</CodeBlockTabs>

`/install` redirige a `scripts/install.sh` del repositorio, así que el script que corrés es el del árbol de código. Este script:

1. detecta tu sistema operativo y arquitectura;
2. usa Homebrew si `brew` está en tu PATH (`brew install isaias-alt/tap/vexillum`, o `brew upgrade` cuando la fórmula ya está instalada, como pasa con el viejo comando `vexillum` de la v0.1.x);
3. si no, descarga el archivo del release para tu plataforma y **verifica su checksum sha256** contra el `checksums.txt` del release, y se niega a instalar si no coincide;
4. instala el binario en `/usr/local/bin`, o en `~/.local/bin` cuando no podés escribir en `/usr/local/bin` (avisa si ese directorio no está en tu PATH);
5. comprueba que ahora existe un `vx` que funciona (en el directorio de instalación, el prefijo de Homebrew o tu PATH) y termina con un error si no, nombrando el binario viejo `vexillum` cuando es lo único que encuentra.

Comprobá que funcionó:

```bash
vx --version
```

<Callout title="¿Venís del comando `vexillum`?">
  El ejecutable ahora se llama `vx`, y es el único: no hay un alias `vexillum`. El producto sigue siendo vexillum, y el paquete de Homebrew mantiene su nombre (`brew install isaias-alt/tap/vexillum` instala el ejecutable `vx`). Corré `vx upgrade` una vez en cada proyecto que hayas inicializado antes - mirá [Migrar de vexillum a vx](/es/docs/get-started/upgrading#migrar-de-vexillum-a-vx).
</Callout>

## Instalá lo que vexillum orquesta

vexillum no instala sus herramientas; las verifica.

| Herramienta | Para qué | Requerida |
| --- | --- | --- |
| [Claude Code](https://claude.com/claude-code) | el commander y cada soldier | sí |
| [herdr](https://herdr.dev) | los panes donde corren los soldiers | sí |
| `gh` (GitHub CLI) | `vx ship`, y aterrizar un PR enviado | solo para eso |
| `tmux` | backend de control opcional | no |

Corré la verificación cuando quieras:

```bash
vx doctor
```

`doctor` es de solo lectura. Imprime `[ok]` o `[missing]` por cada herramienta, la versión de herdr, `~/.vexillum/`, si el proyecto actual está inicializado y es un repositorio git, y, para un proyecto inicializado, el estado del [bloque de AGENTS.md](/es/docs/concepts/agents-md-slot), si `CLAUDE.md` importa `AGENTS.md`, cada [skill](/es/docs/concepts/skills), si [`models.json`](/es/docs/reference/models-json) es válido, y el hook `Stop` del sentinel: si está registrado, si [encuentra vx desde un entorno mínimo](/es/docs/concepts/sentinel#el-hook-no-depende-de-tu-path) y si hay un sentinel corriendo:

```text
[ok] AGENTS.md vexillum block - current (en)
[ok] CLAUDE.md imports AGENTS.md
[ok] skill vexillum - installed, current
[ok] models.json - valid, 5 profiles
[ok] sentinel Stop hook - registered in .claude/settings.json
[ok] sentinel Stop hook finds vx - found with a minimal environment
[ok] sentinel - running, 1 Stop hook await(s) waiting
```

Sale con código distinto de cero cuando falla un chequeo requerido. Un hook `Stop` que no encuentra vx es un `[warn]` con el arreglo, nunca un fallo.

## Instalación global

Por defecto `vx init` es local: prepara un solo proyecto. Para que el commander aplique en todas las sesiones de Claude Code de la máquina, activalo una vez:

```bash
vx init --global
```

En ese caso no hay un `AGENTS.md` de proyecto, así que el mismo núcleo se escribe, sin marcadores, en `~/.claude/rules/vexillum.md`, que Claude Code carga en cada sesión. Las skills van a `~/.claude/skills/` y se crea `~/.vexillum/config.json` si falta. Corre el mismo flujo de consentimiento que el `init` de proyecto: lista `~/.claude/rules/vexillum.md` como un archivo tuyo que va a cambiar, y pregunta antes.

<Callout type="warn" title="Afecta a todas las sesiones">
  Las reglas globales aplican a **todas** las sesiones de Claude Code de esta máquina, no solo a los proyectos de vexillum. No lo uses salvo que quieras eso. El hook `Stop` del sentinel sigue siendo por proyecto y viene de `vx init` dentro de un proyecto.
</Callout>

Para refrescarlo después de instalar un binario más nuevo, corré:

```bash
vx upgrade --global
```

El archivo de reglas se reemplaza solo cuando no cambió desde que vexillum lo escribió; si lo editaste, `upgrade --global --force` lo reemplaza después de guardar tu versión en `~/.vexillum/backups/rules-vexillum.md`. Las skills instaladas siguen las mismas reglas que en un proyecto. Mirá [Actualización](/es/docs/get-started/upgrading).
