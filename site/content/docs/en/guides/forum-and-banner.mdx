Two commands let agents show you something richer than terminal text.

## forum: review in your browser

```bash
vx forum .vexillum/forum/plan.html
```

Agents write their artifacts to `.vexillum/forum/` in the project. `vx init` adds a `.vexillum/.gitignore` that keeps that folder out of git; any path you pass on the command line still works, including an old `.forum/` folder.

Serves an HTML file the agent wrote to your browser and carries your feedback back to it. One local server per user runs on `127.0.0.1` and stops itself when nothing is connected. You can chat, queue messages, fill in decision forms and annotate elements, then send it all to the agent. A Mermaid diagram becomes an editable whiteboard.

On the agent's side:

| Command | Does |
| --- | --- |
| `vx forum <file>` | opens or resumes the session and returns right away |
| `vx forum poll <file>` | blocks until you send feedback; `--reply` shows an answer in the panel |
| `vx forum end <file>` | ends the session |
| `vx forum stop` | shuts the background server down |

Sessions are identified by the file's absolute path. forum is built into the binary: no Node, no `npx`, no network.

### The server stays put

The server tries hard not to move or disappear under an open tab:

- **Same port.** It records the port it bound in `~/.vexillum/forum/last-port` and prefers it on the next start (waiting a few seconds for the previous server to release it), so an open tab keeps working. Only if that port stays taken by something else does it fall back to a free one and record that.
- **No replacing a server in use.** After you upgrade vexillum, a running server may come from an older build. It is replaced by the new build only when it has no open session, no connected tab and no waiting poll. Otherwise the new `vx` reuses it when its protocol is compatible, and stops with an error telling you what to do when it is not (finish or end the sessions and close the tabs, or run `vx forum stop`). A server too old to report its activity is reused, never stopped.
- **Tabs recover on their own.** When the server does restart, an open tab shows a reconnecting banner and retries on its own against the same address. Sessions, queued messages and the transcript are restored from disk, and the session link keeps working.

The agent's playbook is the `forum` [skill](/docs/concepts/skills), installed by `vx init` (full text on [Skill: forum](/docs/reference/skills/forum)).

## banner: publish publicly

```bash
vx banner report.html
```

<Callout type="warn" title="This publishes to a third party">
  `banner` inlines local assets into the HTML and POSTs it to a third-party hosting service (ht-ml.app by default). The page is public unless you pass `--private` or `--password`. It is your decision, per page, to publish.
</Callout>

It prints the page URL and an `update_key`, shown **once** and never stored by vexillum. It is the only credential that can update or unpublish the page; lose it and the page can never be changed. `--unpublish` replaces the page with a placeholder behind a discarded password, since there is no real delete. See the [`banner` reference](/docs/reference/cli/banner) for every flag and size cap.
