title: Quickstart
description: From a fresh install to your first landed mission.
---

You need vexillum, Claude Code and herdr installed. See [Install](/docs/get-started/install).

## 1. Prepare your project

From the root of a git repository:

```bash
vx init
```

`init` changes files of yours, so it tells you which ones and asks first. Step by step:

1. **The notice.** It lists the files of yours it is about to change, then vexillum's own files:

   ```text
   vx init will change these files of yours in /path/to/project:
     AGENTS.md                  add the vexillum block
     CLAUDE.md                  create it with the @AGENTS.md import, so Claude Code sees the block
     .claude/settings.json      add the sentinel Stop hook
   It also writes vexillum's own files: .vexillum/config.json; .vexillum/.gitignore; .vexillum/models.json; .claude/skills/ (vexillum, forum and muster, you are asked first).
   Continue? [Y/n]
   ```

   Answer `n` and nothing is changed.
2. **The [AGENTS.md slot](/docs/concepts/agents-md-slot).** The commander core is written between markers in your `AGENTS.md` (created if missing), in the language it detects there. You confirm or override the language.
3. **The CLAUDE.md import.** `CLAUDE.md` gets the line `@AGENTS.md` so Claude Code sees the block. An existing `CLAUDE.md` is edited only after a second question.
4. **The [skills](/docs/concepts/skills).** `Install the vexillum, forum and muster skills? [Y/n]`. Yes writes them to `.claude/skills/`.
5. **[`models.json`](/docs/reference/models-json).** `.vexillum/models.json` is written with the default model and effort profiles. An existing one is never overwritten.
6. **The sentinel hook.** An async `Stop` hook in `.claude/settings.json` (a one-line command that runs `vx sentinel await` and finds `vx` without relying on your `PATH`) lets the sentinel wake the commander. Existing settings and hooks are merged, never overwritten.

It also creates `~/.vexillum/` if it is missing, and running `init` again changes nothing that is already in place.

Without a terminal (scripts, CI) `init` asks nothing and changes nothing unless you pass `--yes`:

| Flag | Effect |
| --- | --- |
| `--yes`, `-y` | Accept every question, including editing an existing `CLAUDE.md` and installing the skills. |
| `--skills` | Install the skills without asking. |
| `--no-skills` | Do not install the skills, without asking. |
| `--lang en\|es` | Language of the AGENTS.md block, instead of detecting it. |

<Callout title="Commit the scaffold early">
  `vx land` refuses to run while your checkout is dirty, and a fresh `init` leaves new files uncommitted. Commit `AGENTS.md`, `CLAUDE.md`, `.claude/` and `.vexillum/` before you dispatch your first mission.
</Callout>

## 2. Check the environment

```bash
vx doctor
```

Everything required should read `[ok]`.

## 3. Start the commander inside herdr

Open a herdr pane, `cd` into the project and start Claude Code. `vx dispatch` needs `HERDR_WORKSPACE_ID`, which herdr sets in the panes it manages; outside one it refuses to dispatch.

## 4. Ask for work

```text
> dispatch a soldier to fix the flaky login test
```

The commander runs `vx dispatch "fix the flaky login test" --kind mission`, which prints the task id, the camp branch (`vexillum/<task-id>`), and `status=running`. The first dispatch also starts the sentinel in the background.

You can keep talking to the commander while the soldier works. That is the magic of **vexillum**.

## 5. Hear back

When the soldier settles (done or blocked), the sentinel wakes the commander, which reports to you. To look yourself:

```bash
vx status
```

## 6. Land it

When the mission is done, review it and tell the commander to land it. It runs:

```bash
vx land <task-id>
```

That fast-forwards your checkout to the mission's branch and returns the camp to the pool. If you want a reviewed pull request instead, see [Land vs ship](/docs/guides/land-vs-ship).
