Start with `vx doctor`: it names what is missing.

| Message | Cause and fix |
| --- | --- |
| `project not initialized, run 'vx init' first` | `dispatch` found no `.vexillum/config.json`. Run `vx init` at the project root. |
| `current directory is not a git repository` | `init` needs a git repository. |
| `HERDR_WORKSPACE_ID is not set - dispatch must run from inside a herdr-managed pane` | Start Claude Code in a pane herdr manages; `dispatch` and `redispatch` refuse elsewhere. |
| `running from inside ... which looks like a vexillum-managed camp` | You are in a path under `~/.vexillum`. `cd` back to the real project root. |
| `not running in a terminal, so nothing was changed.` | `init` or `upgrade` found no terminal to ask in. Re-run with `--yes` (add `--skills` or `--no-skills` to decide about the skills). |
| `no answer (input closed or not understood) - nothing further was changed; re-run with --yes to accept without questions` | A question got no usable answer, so the run stopped. Re-run, or pass `--yes`. |
| `AGENTS.md: the vexillum block was edited by hand, so it is left as it is` | You edited inside the block. `vx upgrade --force` replaces it after saving yours to `.vexillum/agents-md-slot.backup.md`. See [The AGENTS.md slot](/docs/concepts/agents-md-slot). |
| `AGENTS.md: the vexillum block is malformed` | Broken markers. `vx upgrade` lists the repairs and asks first. |
| `a sentinel is already running (pid N)` | Fine: there is one per machine. Do not start another. |
| `[warn] sentinel` in `vx doctor`: more than one sentinel alive, a different version than the binary, or a binary changed since it started | A stale sentinel is still running after an upgrade or rebuild. It normally retires by itself within seconds; if it does not, stop the pid doctor names with `kill <pid>`. The next `vx dispatch`, `vx prompt` or Stop hook await starts a current one. Never use `pkill`. See [Staying current](/docs/concepts/sentinel#staying-current). |
| `vx: not found, so the sentinel Stop hook cannot wake the commander ...` (stderr of the hook) or `[warn] sentinel Stop hook finds vx` in `vx doctor` | The hook's shell has no `vx` on its `PATH` and none in `~/.local/bin`, Homebrew or `/usr/local/bin`. Install `vx` in one of those, or put its directory on `PATH`. If the hook was written with a bare `vx sentinel await`, run `vx upgrade` to rewrite it. See [Sentinel](/docs/concepts/sentinel#the-hook-does-not-depend-on-your-path). |
| `.claude/settings.json has invalid JSON, leaving it untouched` | Fix the JSON, then run `vx init` again to add the hook. |
| `no tasks yet in this project.` after moving the project | The state key follows the path; see [State](/docs/concepts/state). |

## Landing and striking

| Situation | What to do |
| --- | --- |
| `land refused` | Your checkout is dirty, or the branch diverged from the base. Commit or stash, or ask the soldier to rebase. See [Parallel missions](/docs/guides/parallel-missions). A dirty checkout is often just `init`'s uncommitted scaffold. |
| `landed, but automatic strike failed` | The merge is not undone. Run `vx strike <task-id>` by hand. |
| `strike refused` | The camp has uncommitted changes or unlanded commits. Land the work first. For a shipped mission the refusal says to merge the pull request and run `git pull` on the base branch, then retry. With `gh` logged in, a merged PR whose merge commit is on the local base counts as landed. See [How it ends](/docs/guides/land-vs-ship#how-it-ends). |
| `strike refused: ... merge commit is not on <base> yet` | The PR merged on GitHub but your local base does not have it. Run `git pull` on the base branch, then `vx strike` again. |
| The general confirmed the camp's work is already on the base or abandoned, and strike still refuses | `vx strike <task-id> --discard` strikes anyway and prints each commit and change it threw away. Only with the general's approval. |
| `strike refused: scout task ... has no report` | The report is the scout's work product. Have it write the report, or pass `--force`. |
| `'gh' is not installed` | `ship`, and landing a shipped PR, need the GitHub CLI. |
| `vexillum failed at <step>, refusing to push` | A tribunal step failed; nothing was pushed. Fix it in the camp and ship again. |
| `review blocked: N blocking finding(s)` | The adversarial review found an error or warning (info never blocks). Read the findings in the output; fix them in the camp, or retry with `ship --fix` for the `auto-fix` ones. |
| `review blocked: incomplete coverage` | The reviewer did not report reading every changed file. Ship again. |
| `task ... is running, not interrupted` | Only an `interrupted` task can be re-dispatched. |

## A soldier seems stuck

Check `vx status`. `blocked` is waiting on you: use [`decide`](/docs/reference/cli/decide). `unconfirmed` or `interrupted` need a look at the camp; see [Blocked and interrupted](/docs/guides/blocked-and-interrupted). If the commander never reports a settled soldier, confirm the sentinel runs (`~/.vexillum/sentinel.log`) and that `vx doctor` reports the `Stop` hook as registered and finding vx (`[ok] sentinel Stop hook finds vx`).
