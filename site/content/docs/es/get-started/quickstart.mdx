Necesitás vexillum, Claude Code y herdr instalados (ver: [Instalación](/es/docs/get-started/install)).

## 1. Preparar tu proyecto

Desde la raíz de un repositorio git:

```bash
vx init
```

`init` cambia archivos tuyos, así que te dice cuáles y pregunta antes. Paso a paso:

1. **El aviso.** Lista los archivos tuyos que está por cambiar, y después los archivos propios de vexillum:

   ```text
   vx init will change these files of yours in /path/to/project:
     AGENTS.md                  add the vexillum block
     CLAUDE.md                  create it with the @AGENTS.md import, so Claude Code sees the block
     .claude/settings.json      add the sentinel Stop hook
   It also writes vexillum's own files: .vexillum/config.json; .vexillum/.gitignore; .vexillum/models.json; .claude/skills/ (vexillum, forum and muster, you are asked first).
   Continue? [Y/n]
   ```

   Si respondés `n`, no se cambia nada.
2. **El [slot de AGENTS.md](/es/docs/concepts/agents-md-slot).** El núcleo del commander se escribe entre marcadores en tu `AGENTS.md` (se crea si falta), en el idioma que detecta ahí. Confirmás o cambiás el idioma.
3. **El import en CLAUDE.md.** `CLAUDE.md` recibe la línea `@AGENTS.md` para que Claude Code vea el bloque. Un `CLAUDE.md` existente se edita solo después de una segunda pregunta.
4. **Las [skills](/es/docs/concepts/skills).** `Install the vexillum, forum and muster skills? [Y/n]`. Si decís que sí, las escribe en `.claude/skills/`.
5. **[`models.json`](/es/docs/reference/models-json).** `.vexillum/models.json` se escribe con los perfiles de modelo y effort por defecto. Uno existente nunca se pisa.
6. **El hook del sentinel.** Un hook `Stop` asíncrono en `.claude/settings.json` (un comando de una línea que corre `vx sentinel await` y encuentra `vx` sin depender de tu `PATH`) permite al sentinel despertar al commander. Los settings y hooks existentes se fusionan, nunca se pisan.

También crea `~/.vexillum/` si falta, y volver a correr `init` no cambia nada de lo que ya está en su lugar.

Sin terminal (scripts, CI) `init` no pregunta nada y no cambia nada salvo que pases `--yes`:

| Flag | Efecto |
| --- | --- |
| `--yes`, `-y` | Acepta todas las preguntas, incluso editar un `CLAUDE.md` existente e instalar las skills. |
| `--skills` | Instala las skills sin preguntar. |
| `--no-skills` | No instala las skills, sin preguntar. |
| `--lang en\|es` | Idioma del bloque de AGENTS.md, en lugar de detectarlo. |
| `--global` | Prepara todos los proyectos de esta máquina en vez de este. |

Para que el commander aplique en todas las sesiones de Claude Code y no proyecto por proyecto, mirá [Instalación global](/es/docs/get-started/install#instalación-global) (`vx init --global`, opt-in, afecta a todas las sesiones).

<Callout title="Commiteá el scaffold temprano">
  `vx land` se niega a correr con el checkout sucio, y un `init` recién hecho deja archivos nuevos sin commitear. Commiteá `AGENTS.md`, `CLAUDE.md`, `.claude/` y `.vexillum/` antes de despachar tu primera mission.
</Callout>

## 2. Verificar el entorno

```bash
vx doctor
```

Todo lo requerido debería decir `[ok]`.

## 3. Iniciar el commander dentro de herdr

Abrí un pane de herdr, hacé `cd` al proyecto e iniciá Claude Code. `vx dispatch` necesita `HERDR_WORKSPACE_ID`, que herdr define en los panes que administra; fuera de uno se niega a despachar.

## 4. Pedir trabajo

```text
> dispatch a soldier to fix the flaky login test
```

El commander corre `vx dispatch "fix the flaky login test" --kind mission`, que imprime el id de la tarea, la branch del camp (`vexillum/<task-id>`) y `status=running`. El primer dispatch también inicia el sentinel en segundo plano. 

Podés seguir hablando con el commander mientras el soldier trabaja. Esa es la magia de **vexillum**.

## 5. Enterarte

Cuando el soldier termina (done o blocked) el sentinel despierta al commander, que te reporta. Para mirar vos mismo:

```bash
vx status
```

## 6. Aterrizarla

Cuando la mission está done, revisala y decile al commander que la aterrice. Corre:

```bash
vx land <task-id>
```

Eso hace fast-forward de tu checkout hasta la branch de la mission y devuelve el camp al pool. Si preferís un pull request revisado (ver: [Land vs ship](/es/docs/guides/land-vs-ship)).
